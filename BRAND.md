# Nexora brand guide

[Türkçe](BRAND.tr.md) · [Profile](README.md) · [Governance](GOVERNANCE.md)

## Purpose

Nexora is an independent developer brand building open-source tools for developers and teams. The shared promise is **Local control. Verifiable results.** A product should explain who controls the data, what it does and what evidence supports its claims.

VoiceBridge is the current flagship and beta focus. ProofGate, ReproPack, AccessLease and Nexora FrameLab remain distinct products with their own release scope and licenses. Do not imply that every product shares one license, maturity level or hosted service.

## Name and visual identity

- Use **Nexora** for the brand and **nexora-studio-tr** for the GitHub account. Use each product's established spelling.
- Keep the existing blue/silver N emblem, avatar and [header](assets/header.webp). Do not add “Store” to portfolio branding.
- Palette for future supporting material: midnight `#050B18`, electric blue `#087DFF`, cyan `#27D7FF`, silver `#DCE6F2`, white `#F7FAFF`. These are design tokens, not a claim about the exact pixels in existing artwork.
- Use blue for emphasis and silver/white for readable text on a dark background. Keep glowing effects in artwork; use plain, high-contrast type for instructions. Never rely on color alone to communicate status.
- Leave clear space around the emblem. Keep essential text out of avatar crops and provide descriptive alt text for images.

## Voice

Write in direct, concrete language. English is the default entry point; keep the Turkish counterpart equivalent in scope. Use first-person singular for authorship unless other maintainers actually join.

Lead with the problem and useful behavior, then show a demo or setup path. Put alpha status and material limits beside the claim they qualify. Prefer a small working example to a long feature list.

| Prefer                                                                 | Avoid                                              |
| :--------------------------------------------------------------------- | :------------------------------------------------- |
| “Personal Turkish/English captions, processed on the host's hardware.” | “Perfect real-time translation for everyone.”      |
| “Compared two compatible captures; live CS2 validation is pending.”    | “Massive guaranteed FPS gains.”                    |
| “Windows and Ubuntu source checks passed at this commit.”              | “Production-ready” based only on automated checks. |

## Product presentation

Every repository should make these easy to find: the user's problem, a representative image/demo, a supported setup path, the current tagged release, validation scope, license, contribution guide and private security-reporting path. Distinguish recorded/synthetic demos from live service behavior.

Release notes should name the resulting behavior, link the exact source and checks, explain installation or migration changes, and state unresolved acceptance gates. Keep the previous release's artifacts and identity intact.

## Growth

Current outreach invites reproducible beta feedback, starting with two independent VoiceBridge installations. Publish only approved announcements in relevant communities and follow their rules. Do not promise stars, purchases, performance improvements or selection by an external support program. User evidence determines the next investment.
